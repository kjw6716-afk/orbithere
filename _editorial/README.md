# ORBIT 에디터 운영

## 작성과 발행

우주 이야기는 공식 자료를 읽고 작성한 한국어 해설입니다. 일반 이용자의 글이나 실제 관측 후기로 가장하지 않습니다.
첫 화면과 목록에는 `ORBIT 에디터`를 표시합니다. 글 상세의 작성자 아래에는 `AI가 공식 자료를 바탕으로 작성한 글입니다.`를 한 번 명확하게 표시하고, 원문 출처와 자료 확인 날짜를 유지합니다.

1. ChatGPT Work 예약 작업이 **매일 오전 08:00(KST)** 공식 자료를 조사하고 서로 다른 질문을 다룬 글 **하루 두 편과 각 글에 맞춘 새 표지 두 장**을 만들어 **날짜별 PR 한 개**에 담습니다. 하루 두 편은 새 글 작성 목표이며 발행 상한이 아닙니다. 놓친 날짜의 미완성 슬롯과 미발행 글도 매 실행에서 확인하고 함께 보완합니다.
2. **2026-10-07 운영자의 명시적 상시 승인**에 따라 예약 작업이 원고·공식 출처·문체·표지의 내용과 품질을 검토합니다. 원고, 표지의 두 WebP 크기, 글별 이미지 연결, 생성 기록이 모두 갖춰지고 스키마·이미지 검사와 현재 PR head의 필수 CI가 통과하면 우주 이야기 전용 PR을 자동 병합합니다. 병합 직전 최신 head SHA를 다시 확인하고 그 SHA를 기대값으로 사용합니다. 사람이 개별 검토했다고 표시하지 않으며 저장소의 보호 규칙·필수 검사를 바꾸거나 우회하지 않습니다.
3. `우주 이야기 발행` Actions가 승인된 대기열에서 **발행 가능일이 된 미발행 글을 모두** 발행합니다. 하루 발행 수 제한은 없습니다. 매일 아침(KST 08:43 예정), 콘텐츠 병합, 수동 실행으로 동작합니다. 공개 HTML·사이트맵·`/rss.xml`을 함께 갱신하며 예약 실행은 지연될 수 있습니다.
4. 승인된 글이 없거나 검사가 실패하면 새 글을 발행하지 않고 기존 글을 유지합니다. 여러 편을 함께 발행할 때도 실제 실행일의 한국 날짜를 기록하며, 누락 날짜로 소급하거나 미래 발행일을 앞당기지 않습니다. 이미 발행된 ID는 다시 발행하지 않습니다.

초안 글과 새 표지 생성은 **Work 예약 작업**이 담당하고, GitHub Actions 자체는 AI 글이나 이미지를 생성하지 않습니다.
Work 자동화가 중지되거나 GitHub 연결이 해제되면 초안 생성도 중지됩니다. 이미지 생성 도구가 없거나 실패하면 완성된 원고를 보존하고 해당 PR을 미완성 초안으로 남깁니다. 기존 공용 표지로 대신한 뒤 새 이미지 생성이 완료됐다고 보고하지 않습니다. 승인된 글을 다 발행한 뒤에는 새 글이 나오지 않습니다.
이 상시 승인은 우주 이야기의 검증 후 자동 병합·발행과 누락분 보완에 적용합니다. 근거·표지·검사가 미완성인 PR은 보류하고 다음 실행에서 이어서 처리합니다.
표지의 제작·파일·검사·재실행 절차는 [일일 글·이미지 작업 절차](IMAGE_WORKFLOW.md)를 따릅니다.

### 발행 수 제한 해제 (2026-09-27)

운영자 요청으로 하루 한 편 제한과 특정 날짜·글 조합만 허용하던 예외를 제거했습니다.
기존 2026-09-12의 세 편과 2026-09-26의 두 편도 원래의 실제 발행일과 원고 해시를 유지합니다.
`--publish-next`는 실행당 다음 한 편을, `--publish-due`는 승인된 발행 가능 원고 전체를 발행합니다.
둘 다 같은 날 여러 번 실행할 수 있으며, ID 중복·공개 원고 해시 변경·미래 발행일·시계 역행 검사를 유지합니다.

발행 날짜는 첫 화면·메인 카드·목록·본문 화면에 표시하지 않습니다. 중복 방지 장부와 검색용 실제 발행일,
출처의 자료 확인 날짜는 유지합니다. 첫 화면에는 모든 공개 글을 발행 순서대로 연결한 가로 카드 레일을 제공합니다.
첫 글이 가운데, 같은 크기의 카드가 양옆에 놓이며 전체가 왼쪽에서 오른쪽으로 초당 20px씩 끊김 없이 이동합니다.
데스크톱(너비 1,200px 이상)에서는 양끝 32px 여백을 두고 레일을 화면 너비에 맞춥니다. 카드 크기는 유지하며 반복 사본 수를 화면 폭에 따라 조정해 울트라와이드와 창 크기 변경에서도 양끝을 채웁니다.
운영자의 후속 요청에 따라 화살표·정지 버튼·카운터와 4초 단위의 개별 전환을 제거했습니다. 포인터·키보드 초점·터치 중에는 이동을 쉬고,
탭이 숨겨지거나 화면 밖에 있을 때도 멈춥니다. 글이 추가되어도 이동 속도는 같으며, 반복 표시용 사본은 키보드·스크린리더에서 제외합니다.
동작 줄이기 설정이나 JavaScript 없는 환경에서는 자동 이동 없이 가로 스크롤로 모든 글을 읽을 수 있습니다.

`_editorial/`은 기존 GitHub Pages Jekyll 배포에서 웹 페이지로 내보내지 않는 작업 폴더입니다.
**GitHub 저장소와 PR 자체는 공개**이므로 초안·검토 메모에도 비밀값과 개인정보를 넣지 마세요.
`.nojekyll`이나 배포 방식 변경 시 이 제외 조건을 다시 검토하세요.

## 한 편의 기준

- 독자가 궁금해할 질문 하나를 중심으로 본문 1,000~1,500자, 3~6개 소제목. 검사는 1,600자까지 허용합니다.
- 친근한 한국어 존댓말. 용어는 처음 나올 때 풀어 쓰고 비유는 사실과 구분합니다.
- 공식 원문 1~5개를 **실제로 읽어** 출처를 달고 수치·날짜·명칭·적용 범위를 대조합니다.
- `factChecks`에 중요한 주장 2~10개와 근거 위치/요지를 한국어로 기록합니다. 예약 작업이 실제 공식 원문과 대조하며, 자동 검사만으로 사실 정확도가 입증되지는 않습니다.
- 자료는 NASA·ESA·KASI·IMO·NOAA 또는 해당 기업의 공식 페이지를 사용합니다. 기업의 미래 계획은 확정된 성과로 쓰지 않습니다. 출처가 불확실하면 작성/발행을 보류합니다.
- 매번 기존 발행 글, 대기열, 열린 초안 PR을 먼저 확인해 제목뿐 아니라 주제 중복도 피합니다. 달·행성·별·탐사·관측을 번갈아 다룹니다.
- 원문 전문을 번역·재게시하지 않고 독자적인 구성으로 설명합니다. 외부 이미지는 사용 권한과 표기 조건을 확인한 경우에만 별도 변경으로 추가합니다.
- 관측하지 않은 경험, 감상, 사진을 실제 후기처럼 만들지 않습니다. 실시간 하늘·발사 정보는 별도 현재 자료가 없으면 단정하지 않습니다.
- 새 글마다 고유한 편집 삽화를 생성합니다. 기존 8종 공용 표지와 카테고리 기본 이미지는 기존 글의 표시를 위해 유지하며, 새 글의 맞춤 표지 생성 완료 조건으로 사용하지 않습니다. AI 삽화 안내를 유지하고 원고 JSON에는 이미지 필드를 추가하지 않습니다.
- 첫 글을 시작으로 초기 콘텐츠의 문체와 정확도를 검토합니다. 검토되지 않은 생성물을 공개 발행하지 않습니다.

## 파일 형식과 명령

`articles/moon-face-and-phases.json`을 스키마 예시로 사용합니다. `id`는 짧은 영문 소문자 slug이고 파일명과 같아야 합니다.
`publishAfter`는 발행 가능한 첫 한국 날짜입니다. 미래일이면 기다리고 과거일이면 다음 실행일에 발행합니다.
`sections[].sources`는 1부터 시작하는 `sources` 배열 번호입니다. HTML 대신 일반 텍스트를 넣습니다.

```sh
# 새 초안 파일의 형식과 기존 공개 페이지의 일치 확인 (발행하지 않음)
python scripts/stories.py --check
python -m unittest discover -s tests -p 'test_stories.py'

# main에 승인된 대기열에서 발행 가능한 글 모두 발행하고 정적 HTML 생성 (Actions 기본값)
python scripts/stories.py --publish-due

# 발행 가능한 다음 한 편만 발행 (같은 날 추가 실행 가능)
python scripts/stories.py --publish-next

# 템플릿/메뉴 수정 후 기존 발행분 다시 렌더링 (새 글 발행 없음)
python scripts/stories.py
python scripts/site_navigation.py

# 이미 발행한 본문을 출처와 대조해 수정했을 때만
python scripts/stories.py --accept-correction ARTICLE_ID
```

완료된 초안 PR은 새 article JSON **두 개**, 글마다 새로 생성한 표지의 **640×360·1200×675 WebP 두 개씩**, `data/story-images.json`의 새 글별 연결·alt, 각 표지의 생성 기록을 함께 추가합니다.
예약 작성자는 이 파일 범위에서만 필요한 항목을 추가하며 기존 글·이미지·매핑을 보존합니다. 발행 장부·공개 HTML·사이트맵·RSS·코드·워크플로는 바꾸지 않습니다. 자기 우주 이야기 PR도 위 검토·검사 조건을 충족하면 자동 병합하며, 공개 파일 생성은 기존 발행 Actions가 담당합니다.
PR 본문에 두 글의 전체 본문을 읽을 수 있게 넣고, 각 글의 출처 링크·핵심 사실 대조·희망 발행일·표지 미리보기·최종 생성 프롬프트와 도구·검사 결과를 정리합니다.
날짜별 `codex/orbit-story-YYYY-MM-DD` 브랜치와 PR 한 개를 사용합니다. 첫 번째·두 번째 글을 구분해 그날의 작성 슬롯을 기록하고,
재실행 전 같은 한국 날짜의 열린·병합된 PR과 승인 대기열·발행 기록을 확인합니다. 이미 두 편이 있으면 새로 만들지 않고,
열린 PR은 기존 원고·완성된 표지를 유지한 채 빠진 원고 또는 이미지 산출물만 보완합니다. 글이 두 편 있어도 표지가 빠져 있으면 작업이 완료된 것이 아닙니다. 두 글끼리와 기존 글 사이의 주제·핵심 질문 중복도 피합니다.
공식 근거를 확인하지 못하거나 표지 생성·검사가 실패한 슬롯은 억지로 채우지 말고 부족한 이유와 재시도할 항목을 PR에 기록합니다. 병합된 날짜별 PR에 누락이 있으면 원래 PR·날짜·슬롯을 연결한 복구 PR로 빠진 항목만 보완하고 같은 검토·검사·자동 병합 절차를 적용합니다. 누락분은 새 일일 두 편과 별개로 처리하되 완성된 글을 다시 만들지 않으며, 실제 생성일·자료 확인일·발행일을 과거 슬롯 날짜로 소급하지 않습니다.

`published.json`은 실제 발행일과 원고의 SHA-256을 보관합니다. 같은 날 여러 번 실행해도 중복 발행되지 않습니다.
RSS에는 `published.json`에 기록된 공개 글 중 최신 20편만 넣고 네이버 권장에 맞춰 본문 전체와 동일 도메인 URL을 제공합니다. 전체 공개 URL은 사이트맵에 계속 보관합니다.
원고 변경은 명시적인 correction 기록 없이는 차단하며 장부와 생성 HTML을 같은 커밋으로 저장합니다.
동일 main을 갱신하는 뉴스 작업과 concurrency 그룹을 공유합니다. 외부 푸시와 경합하면 강제 갱신 없이 실패하며 최신 main에서 재실행합니다.

## 이야기 탐색·추천·공유

목록의 `전체 / 달과 행성 / 별과 우주 / 우주 탐사 / 관측 이야기` 필터는 검색어와 함께 적용됩니다. 대표 이야기와 일반 카드는 각 글을 한 번씩만 표시하며, 결과 건수에는 둘 다 포함합니다. 선택한 주제와 검색어는 브라우저 안에서만 처리합니다. JavaScript를 사용할 수 없어도 전체 공개 목록과 본문을 읽을 수 있습니다.

상세 페이지의 `함께 읽으면 좋은 이야기`는 생성기가 발행 장부에 있는 글 중 최대 세 편을 고릅니다. 현재 글과 같은 ID·제목, 중복 후보는 제외합니다. 같은 분야, 공통 공식 출처 수, 같은 관측 도구 연결 순으로 비교하고 동률이면 최신 발행 순서를 따릅니다. 공개된 다른 글이 적으면 있는 만큼만 보여줍니다. `읽고 나서, 하늘로` 관측 도구 연결과 출처·주소 복사 기능을 함께 유지합니다. 추천을 바꾸기 위해 승인된 원고나 발행 해시를 수정하지 않습니다.

공유 메타데이터는 글 제목·소개·고유 주소와 `data/story-images.json`의 표지를 사용합니다. OG·Twitter 카드에는 외부에서 접근할 수 있는 `https://orbithere.com/images/stories/<표지 키>-1200.webp`를 넣습니다. 새 글도 승인·발행 시 같은 생성기를 거치므로 별도 HTML 편집이 필요 없습니다.

템플릿 변경 후에는 `python scripts/stories.py`로 기존 공개 글을 다시 생성하고, Python 검사·`node tests/stories.mjs`·링크 검사를 실행합니다. PC·모바일에서 검색과 주제 조합, 결과 없음과 초기화, 추천 링크와 키보드 초점, 이미지 로딩을 확인합니다. 배포 후에는 실제 HTML 메타데이터와 이미지의 HTTP 응답을 확인합니다. 외부 공유 서비스의 카드 표시·캐시 갱신은 별도 확인이므로, 실제로 보지 않았다면 확인했다고 보고하지 않습니다.

이전 기록을 자동으로 열거나 삭제하지 않습니다. 해당 기기에서 확인·복사·내려받기·명시적 삭제가 가능합니다.
새 기록 저장, 서버 전송, 다른 기기로의 자동 이전은 없습니다.
