# 한국어 뉴스 핵심 요약

`data/news-summaries.json`은 공식 원문과 대조한 한국어 제목·요약입니다.
원문 전문이나 이미지, 모델 입력용 본문은 저장하지 않습니다.
2시간마다 갱신되는 `data/news.json`과 별도로 관리해 수집 작업과 편집 작업이 서로 덮어쓰지 않습니다.

## 작성과 갱신

1. 최신 main의 이 문서, `data/news.json`, `data/news-summaries.json`, 열린 뉴스 요약 PR을 확인합니다.
2. `python3 scripts/news_summaries.py --pending`으로 요약이 없는 기사를 확인합니다. 최신 기사부터, 출처가 고르게 포함되도록 작업합니다.
3. 각 기사의 **공식 원문 본문 또는 공식 PDF**를 실제로 읽습니다. 제목·검색 요약만으로 내용을 추측하지 않습니다. 동적 페이지는 정상적으로 표시된 해당 기사 본문을 확인합니다.
   SpaceX Updates처럼 처음에는 머리말만 보이는 페이지는 기사 제목과 본문이 나타나는지 다시 확인합니다. 2026-09-13 확인한 구조는 기사별 `.update` 영역이었으며, 선택자는 실행 시 실제 DOM과 대조합니다. 처음 읽은 화면에 본문이 없다는 이유만으로 접근 불가로 판정하지 않습니다.
4. 핵심을 독립적인 한국어 2~3문장으로 작성합니다. 각 문장은 10~240자이며 HTML·줄바꿈 없이 저장합니다. 발사 예정과 성공, 계약 상한과 개별 수주액, 후보 선정과 확정 계약을 구분합니다. 기업의 주장은 해당 기업의 발표임을 드러냅니다.
5. 과거 기사에 있는 예정·목표를 현재의 성과처럼 바꾸지 않습니다. 영상·중계 안내는 그 성격과 원래 날짜를 설명합니다. 공식 원문을 확인할 수 없으면 해당 항목은 건너뜁니다.
6. `id`, `source`, `url`, `publishedAt`은 뉴스 항목에서 그대로 복사하고, `titleOriginal`은 원제와 정확히 일치시킵니다. `titleKo`는 원제와 대조한 자연스러운 한국어 제목입니다.
7. `summaryKo`는 문장 배열, `checkedAt`은 실제 원문 확인 날짜(YYYY-MM-DD), `method`는 원문 대조가 끝난 경우에만 `source-checked`입니다. 이는 사람이 검토했다는 의미나 사실 정확도 인증이 아닙니다.
8. 새 내용을 쓰는 동안 기존 항목은 보존합니다. 동일 ID 기사가 수정됐으면 그 기사만 새 원문과 대조해 교체합니다. 최대 256개까지 보관하고, 초과 시 현재 뉴스에 없는 오래된 항목부터 정리합니다.
9. `python3 scripts/news_summaries.py`, `npm run test:news`, `npm run test:navigation`으로 확인하고, PR에 원문 링크와 숫자·일정 확인 메모를 남깁니다. 저장소 규칙에 따라 `PROJECT_STATUS.md`도 변경 내용에 맞춰 갱신합니다.

## 공개와 자동화

- 뉴스 수집은 GitHub Actions에서 2시간마다, 새 요약 확인은 별도의 Work 예약 작업에서 2시간마다 진행합니다. 수집은 UTC 짝수 시각 17분, 요약 확인은 그 뒤인 한국 시간 홀수 시각 45분을 기준으로 예약합니다. 예약 실행은 지연될 수 있으며, 원문 확인·검토에 걸리는 시간 때문에 요약 공개까지 2시간을 보장하지는 않습니다.
- AI는 새로운 요약을 검토 가능한 PR로 준비합니다. 요약 PR은 운영자가 검토·병합한 뒤 공개됩니다.
- 원문을 읽을 수 없거나 요약 PR이 아직 병합되지 않은 기사는 제목과 원문 읽기만 제공합니다.
- 요약 완료 시각이 정해지지 않은 기사에 ‘준비 중’ 문구를 붙이지 않습니다. 목록 확인 후 4시간을 넘겼으면 저장된 목록과 원문 링크를 유지하면서 확인 시각이 오래됐음을 알립니다.
- 뉴스 요약 예약은 제목이 다른 열린 PR도 요약 파일의 변경 여부를 확인해 중복 작성을 피합니다. 다른 기능을 포함한 PR은 자동 수정하지 않습니다. 이 원문 재확인·중복 방지 규칙은 기존 Work 예약에도 반영했습니다.
- 브라우저는 기사 ID·출처·URL·원제·발행일이 모두 맞고 형식 검사를 통과한 요약만 표시합니다. 요약 파일이 없어도 뉴스 제목과 원문은 읽을 수 있습니다.
- 제목이 그대로인 원문 본문 수정은 자동 감지하지 못합니다. 확인 날짜 이후 변경될 수 있으므로 정정 시 해당 요약도 갱신합니다.
- 우측 슬라이드 패널은 제목 중심의 기존 형태를 유지하고, 핵심 요약은 뉴스 목록에서 읽습니다.

## 갱신 지연 점검

2026-09-14에는 Blue Origin의 공개 목록 접근이 계속 막혀 활성 수집 출처를 AST SpaceMobile로 교체했습니다. 공식 IR의 Issuer Direct 피드에서 ASTS 보도자료만 수집하며 증권 발행·전화회의 일정 공지는 제외합니다. Blue Origin의 기존 원문 대조 요약은 `ARCHIVED_SOURCES`로 검증해 보존합니다. 새 AST 기사 네 건은 정상 표시된 공식 본문을 읽고 한국어 제목·요약을 대조했습니다. 원문의 발행일을 유지하며 과거 발사 예고를 현재 예정이나 새 소식으로 소개하지 않습니다.

2026-09-13 최근 수집 실행은 약 1분 만에 성공했지만, 직전 뉴스 실행과 약 7시간 간격이 있었습니다. 수집 처리 지연과 예약 실행 간격을 구분해야 합니다. 당시 SpaceX·Starlink 수집은 정상이고 Blue Origin은 이전 목록을 보존한 상태였습니다. 이 기록만으로 GitHub 내부의 지연 원인을 확정할 수는 없습니다.

[GitHub 공식 문서](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)는 예약 실행이 부하에 따라 지연·누락될 수 있다고 설명합니다. 현재 예약은 정각을 피한 UTC 17분이며, 임의의 다른 분으로 옮기는 것만으로 개선된다고 보장하지 않습니다.

운영 점검에서는 `data/news.json`의 `checkedAt`, 출처별 `status`·`lastSuccessfulAt`, 최근 뉴스 Actions 실행의 생성 시각·소요시간·결과를 함께 확인합니다. 요약 부재는 별도로 원문 확인 보류와 검토 PR 대기를 구분합니다. 기존 아침 브리핑에 새 지연·장애 및 복구만 포함하며 동일 장애를 반복 통보하지 않습니다.
