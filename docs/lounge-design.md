# 커뮤니티 첫 화면

## 화면과 기존 주소

`/`와 `index.html`에서 자유게시판을 바로 표시합니다. 별도 랜딩 화면이나 리디렉션은 없습니다.
`lounge.html`을 원본 문서로 삼고 `scripts/community_home.py`로 홈을 생성합니다.
메뉴를 수정할 때는 `python3 scripts/site_navigation.py` 실행 후 홈을 다시 생성합니다.
CI의 `test:landing`은 홈 문서가 원본과 일치하는지 먼저 검사합니다.
이야기 발행 생성기는 `main.html`의 안내만 갱신하며 홈을 덮어쓰지 않습니다.

기존 `lounge.html?post=…`, 분류·검색·내 활동 주소와 `main.html#lounge` iframe을 유지합니다.
첫 화면과 직접 게시판에서는 상단 메뉴와 로그인·회원가입을 바로 표시합니다.
다른 도구의 기존 메뉴와 인증·작성·초안 동작은 유지합니다.
루트 로그인 복귀 주소 `/`를 허용하고, 루트 방문 통계는 기존 `board/direct` 조합으로 기록합니다.

## 화면 구성

- 데스크톱은 게시판 약 75%, 보조 소식 약 25%입니다. 860px 이하에서는 소식을 게시판 아래로 배치합니다.
- 성운 배너는 PC 120px이며 모바일에서는 제목·행동 버튼에 맞게 늘어납니다. 본문 뒤에는 단색 면을 사용합니다.
- 목록은 PC 약 48px 높이, 모바일은 제목·작성자·시간 두 줄 구성입니다. 제목과 댓글 본문은 기본 16px 이상을 유지합니다.
- 댓글 위아래 여백은 5px이며 삭제·신고는 옆에 배치합니다. 모바일 행동 버튼의 높이는 44px을 유지합니다.
- 오른쪽은 `최근 대화`와 `관측 사진` 탭입니다. 키보드 좌우/Home/End 이동과 빈 상태·오류·재시도를 지원합니다.
- 기존 공지, 검색, 질문 필터, 내 활동, 글쓰기, 사진, 뉴스 원문 링크를 유지합니다.

## 공개 데이터

`community-feed.js`는 기존 공개 컬럼만 읽습니다. 최근 댓글 6개와 그 원글 제목을 연결하고,
사진 탭을 열 때 사진이 실제 첨부된 최신 게시물 4개를 조회합니다.
사진 여부는 서버에서 필터링해 오래된 사진 글을 최신 일반 글 뒤에서 놓치지 않도록 합니다.
회원 표시는 기존 공개 `member_cards` 경로로 갱신합니다.

이미지는 기존 private 버킷의 허용된 다운로드 경로와 썸네일을 사용합니다.
Blob URL은 교체·오류·페이지 종료 때 해제하고 BFCache 복귀 시 다시 불러옵니다.
타임라인 자체는 계정 생성·조회수 증가·댓글 읽음 처리를 하지 않습니다.
댓글을 누르면 `?post=…&comment=…`로 해당 글을 열고 대상 댓글을 표시합니다.
대상이 첫 20개 밖에 있어도 별도로 조회하며, 이미 연 로그인 창의 포커스를 빼앗지 않습니다.

새 DB 테이블·함수·권한·마이그레이션은 없습니다. 가상 글·댓글·인기·회원 수를 추가하지 않습니다.
사진이나 대화가 없으면 그 상태를 그대로 안내합니다.

## 자산과 검증

기존 `images/nebula-landing-{1200,1600,2000,2430}.{avif,webp}`를 재사용합니다.
AI 생성 이력은 [기존 자산 기록](nebula-and-otter.md)에 있으며 실제 관측 사진으로 표시하지 않습니다.
뉴스에 사진 출처가 없으므로 임의 사진을 붙이지 않습니다.

테스트는 모든 외부 HTTP를 가로채는 기존 로컬 모의 응답으로 실행합니다.
운영 계정·게시물·댓글을 테스트 목적으로 만들지 않습니다.
첫 화면·모바일·글자 확대·키보드·루트 인증 복귀·초안·타임라인·장애 복구를 확인하고,
기존 회원·권한·게시판·천문·뉴스·이야기 검사를 GitHub 배포 전에 통과해야 합니다.
