# 커뮤니티 운영 보완

## 현재 적용 범위

화면은 기존 SQL 011(보안 버전 2)에서 동작합니다. 검색·공유·페이지 이동·기기 노트 저장에는
새 DB 테이블이나 유료 서비스를 요구하지 않습니다. 신고/옛 글 삭제 요청은 기존 reports와
관리자의 report_queue/resolve_report를 사용합니다. 신고자와 일반 이용자는 접수함을 읽을 수 없습니다.

GitHub Pages에 병합하는 것만으로 SQL은 실행되지 않습니다.
`supabase/migrations/20260911204442_community_readiness_hardening.sql`은 **2026-09-12 운영 적용을 완료했습니다.**
처음 적용 요청은 자동 승인 검토에서 보류됐지만, 이후 사용자가 이 운영 DB 변경을 명시적으로 승인했습니다.
Supabase 마이그레이션 버전은 `20260911210425`, 이름은 `community_readiness_hardening`입니다.
저장소 파일명의 생성 시각과 서버의 실제 적용 버전은 서로 다릅니다.
적용 후 보안 버전 2, 기존 콘텐츠 내용 지문 보존, 새 트리거·권한·인덱스를 확인했습니다.
적용 전 함수 정의와 실행 권한을 조회해 복구 경로를 확인했습니다. 이 확인은 전체 DB 백업 또는 복원 시험을 대신하지 않습니다.

## 검토할 SQL의 범위

- `orbit_private.write_events`: 작성자 ID·대상 ID·종류·시각만 기록. 본문·닉네임·IP는 복사하지 않습니다.
  공개/인증 API 역할 모두 스키마·테이블 접근 권한이 없고 RLS를 활성화합니다.
- posts는 분당 3건/시간당 20건, comments는 5건/50건, reports는 5건/30건으로 기존 수치를 유지합니다.
  실제 게시물 삭제와 별개로 성공한 쓰기를 세며 작성자·종류별 트랜잭션 잠금을 사용합니다.
- 1시간이 지난 기록은 다음 정상 글·댓글·신고 저장 시 삭제됩니다. 정기 작업은 설치하지 않습니다.
  계정이 삭제되면 연결된 제한 기록도 삭제됩니다. 기존 콘텐츠는 변경하거나 삭제하지 않습니다.
- 관리 RPC의 비인증 호출 권한과 트리거 전용 함수의 직접 호출 권한을 회수합니다.
  관리자 여부를 확인하는 기존 함수 내부 검증은 유지됩니다.
- 글 전체/채널별, 댓글 스레드의 `(created_at,id)` 탐색 인덱스를 추가합니다.
- 한 트랜잭션으로 실행하며 잠금 획득 제한은 5초입니다. 실패 시 일부만 적용되지 않습니다.

검증: 실제 마이그레이션을 PGlite에서 두 번 실행하고 소유권, 관리자 접근, 비공개 신고,
글/댓글 삭제 후 재작성, 대량 INSERT 롤백, 시간당 제한과 만료 기록 정리를 확인합니다.
PGlite는 단일 연결이므로 병렬 부하 시험을 수행했다고 간주하지 않습니다.

## 재적용·복원 시 참고

1. 대상이 기존 Orbit 프로젝트인지 확인하고 최신 복구 수단/백업 상태를 점검합니다.
   신규 DB에서는 루트의 schema.sql, 002…011을 먼저 적용하고 이 timestamp 마이그레이션을 실행합니다.
   기존 프로젝트에 초기 스키마를 다시 실행하지 않습니다. 레거시 SQL은 CLI migrations 폴더로 자동 이관되지 않습니다.
2. 개인정보처리방침의 아래 제한 기록 안내가 실제 운영과 일치하는지 확인합니다.
3. Supabase 마이그레이션 기능 또는 SQL Editor로 검토한 SQL 전체를 한 번 적용합니다.
4. 새 테이블 접근 차단, 관리자 RPC 권한, 세 종류의 INSERT 트리거, 탐색 인덱스,
   공개 조회와 기존 콘텐츠 보존을 확인합니다. 운영 게시물은 자동 테스트 재료로 생성/삭제하지 않습니다.
5. 처리 결과·적용 시각·마이그레이션 버전을 PROJECT_STATUS에 기록합니다.

개인정보처리방침에 반영한 안내:

> 삭제 후 반복 작성하는 도배를 막기 위해 글·댓글·신고의 작성자 ID, 대상 ID, 종류, 작성 시각을
> 비공개 제한 기록에 보관합니다. 이 기록에는 본문·닉네임·IP 주소를 추가로 저장하지 않습니다.
> 게시물을 지워도 제한 기록은 즉시 삭제되지 않습니다. 작성한 지 1시간이 지나면 다음
> 글·댓글·신고가 정상 저장될 때 함께 삭제되며, 해당 인증 계정 삭제 시에도 제거됩니다.

문제가 발생하면 새 트리거만 제거하고 기존 posts_rate_limit/comments_rate_limit/reports_rate_limit
트리거를 복구하는 별도 검토된 수정으로 대응합니다. 원인 조사 전 기록 테이블이나 콘텐츠를 지우지 않습니다.
기존 함수는 남겨 두므로 트리거 복구에 함수 재작성은 필요 없습니다.

## 운영자가 계속 확인할 것

새 익명 계정을 만드는 공격까지 작성자별 제한으로 막을 수는 없습니다.
Supabase의 가입 제한과 CAPTCHA 설정은 실제 서비스 키 및 가입 흐름 검증 후 별도로 적용합니다.
인증 세션 초기화, 닉네임 중복, 사진 첨부 미지원도 현재 제한입니다.

관리자는 신고함을 정기적으로 확인하고 삭제 요청의 대상과 권한을 검토합니다.
공개 게시판에 비밀번호·인증 코드·신분증을 요구하지 않습니다. 신고 외 일반 비공개 연락 경로는 아직 없습니다.
