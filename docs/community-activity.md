# 내 활동과 새 답글

## 이용 흐름

게시판 헤더의 ‘내 활동’은 같은 브라우저의 기존 Supabase 인증 세션으로 확인합니다.
새 답글이 있으면 해당 대화 목록을 먼저 열고, 없으면 내 글을 엽니다.
활동이 없는 방문자는 계정 생성 없이 안내와 전체 게시판 복귀 링크를 봅니다.
내 글·참여한 글·새 답글에는 검색과 `(created_at,id)` 커서 페이지 이동을 제공합니다.
일반 게시판의 공지는 개인 목록에 별도로 끼워 넣지 않으며, 본인의 공지 글은 내 글에 포함합니다.

- 내 글: 인증된 이용자가 작성한 글.
- 참여한 글: 다른 사람의 글에 본인의 댓글이 현재 남아 있는 대화. 자신의 글과 구분합니다.
- 새 답글: 내 글에 달린 다른 사람의 댓글, 또는 다른 글에 참여한 시점 이후의 다른 사람 댓글 중 아직 확인하지 않은 댓글이 있는 대화.
- 헤더 숫자: 읽지 않은 답글이 있는 대화 수, 최대 `99+`. 글별 숫자: 아직 읽지 않은 댓글 수.

목록 진입·수동 새로고침·쓰기 후·읽음 저장 후 숫자를 다시 확인합니다.
탭에 돌아왔을 때 마지막 확인 이후 60초가 지났으면 숫자를 갱신합니다.
이메일·푸시·지속적인 폴링은 없으며, 이미 열린 상세의 댓글은 기존 댓글 새로고침으로 불러옵니다.
요청 실패를 빈 목록이나 ‘모두 읽음’으로 바꾸지 않고 마지막 확인 결과와 재시도를 제공합니다.

## 읽음과 소유권

`board-activity.js`는 실제로 렌더링된 댓글 중 화면에 10% 이상 나타난 댓글의 ID를 보냅니다.
숨긴 탭·요청 실패·다른 화면으로 이동·인증 계정 변경 시 이전 관찰을 중단합니다.
아직 불러오지 않은 이전 댓글이나 화면을 연 뒤 도착한 답글은 읽음 요청에 포함하지 않습니다.
서버는 댓글별로 기록하므로 기기 시각이나 스레드 전체의 마지막 열람 시각으로 댓글을 건너뛰지 않습니다.
요청은 최대 50개이며 중복 요청은 결과를 바꾸지 않습니다.

`orbit_activity_private.read_comments`는 사용자 ID와 댓글 ID만 보관합니다.
읽음 기록에 본문·닉네임·IP·별도의 열람 시각을 복사하지 않습니다.
RLS SELECT 정책은 `user_id=(select auth.uid())`인 본인 기록만 허용합니다.
비로그인 `anon`은 접근할 수 없고 인증 역할도 테이블에 직접 INSERT/UPDATE/DELETE/TRUNCATE할 수 없습니다.
공개 RPC는 invoker이며, 비공개 스키마의 제한된 쓰기 함수만 검증된 `auth.uid()`와 대화 참여 조건을 확인해 기록합니다.
클라이언트가 사용자 ID를 지정하는 인자는 없습니다. 모든 신규 함수의 search_path는 비어 있습니다.

댓글 또는 인증 계정 삭제 시 해당 기록이 함께 삭제됩니다.
글 삭제 시 연결된 댓글과 읽음 기록도 삭제됩니다.
브라우저 데이터 삭제는 서버 계정·글·읽음 기록을 지우지 않습니다.
익명 세션을 잃거나 다른 기기로 이동하면 이전 활동과 삭제 권한을 이어받을 수 없으며,
같은 닉네임을 입력해도 연결되지 않습니다. 선택적 계정 연결은 별도 후속 작업입니다.

## 운영 적용과 검증

필수 파일은 `supabase/migrations/20260913211703_community_activity.sql`입니다.
GitHub Pages는 SQL을 실행하지 않으므로 UI 배포 전에 적용합니다.
운영에는 2026-09-14 06:30 KST, 버전 `20260913213006_community_activity`로 적용했습니다.
기존 글·댓글의 개수와 내용 지문이 적용 전후 일치했습니다.
신규 기록 0건, RLS 본인 조회 정책, 직접 쓰기 차단, 공개 invoker와 비로그인 실행 차단을 확인했습니다.
운영 글·댓글을 만들거나 지워서 검사하지 않았습니다.

보안 Advisor에서 추가된 `auth_allow_anonymous_sign_ins` 1건은 이 서비스가 익명 **인증** 계정에
본인 읽음 기록 조회를 허용하기 때문입니다. 인증 없는 공개 접근을 뜻하지 않습니다.
익명 글쓰기를 유지하는 기능 요구이며, 다른 계정의 기록은 RLS로 차단합니다.
[Advisor 설명](https://supabase.com/docs/guides/database/database-advisors?queryGroups=lint&lint=0012_auth_allow_anonymous_sign_ins).
기존 Advisor 항목의 대상과 개수는 유지됐습니다.

실제 마이그레이션을 두 번 적용하는 PGlite 검사 144개와 HTTP를 가로챈 실제 Supabase SDK 기반
게시판 검사 140개가 통과했습니다. 본인·타인 권한, 가입 없는 조회, 참여 전후 구분,
댓글·계정 삭제, 페이지 이동, 화면 밖·동시 도착 댓글, 저장 실패 재시도, 새로고침 보존,
일반 공지가 개인 화면으로 복원되지 않는지 및 320·390·1440px 배치를 확인합니다.
PGlite 단일 연결의 검증을 운영 동시 부하 시험으로 간주하지 않습니다.

UI 문제가 생기면 이전 화면으로 되돌려도 기존 공개 읽기·쓰기 RPC는 유지됩니다.
읽음 기록 테이블이나 기존 콘텐츠를 먼저 삭제하지 않습니다.
원인을 확인하고 UI 또는 관련 함수만 수정하며, 저장된 읽음 상태를 보존합니다.
